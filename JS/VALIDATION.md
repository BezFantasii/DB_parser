## Backend в версии 0.3.0

Запущены PostgreSQL в Docker на `127.0.0.1:5433`, нативные API `127.0.0.1:8000` и worker. Живое API-задание «худи мужское» завершилось `succeeded` и сохранило 5 предложений Ozon в PostgreSQL. Отчёт: `backend/test-results/backend-search-live.json`.

`npm.cmd run check:backend:live` дополнительно проверил новый режим расширения целиком: контролируемая исходная страница поиска WB → настоящий HTTP API → настоящий Chrome-worker → живой Ozon → PostgreSQL → виджет. Получены и показаны 5 товаров; отчёт и снимок — `test-results/backend-live-widget.json`, `test-results/backend-live-widget.png`. Исходная страница WB в этом тесте является fixture; серверные товары получены из живой выдачи Ozon. Пользовательские вкладки расширение не открывало и не перенаправляло.

Docker Chromium и живой backend-поиск WB в этой проверке отдельно не подтверждены. Блокировки площадок передаются виджету как ошибки сервера. Подключение и запуск: [backend/EXTENSION.md](../backend/EXTENSION.md).

Новый браузерный тест запускает настоящее расширение в Chromium. Локальный HTTPS-прокси обслуживает контролируемые HTML Ozon/WB и JSON WB: тест не зависит от доступности магазинов и не выдаёт подставные результаты за живую выдачу. TLS-сертификат и ключ создаются только в памяти теста. Флаги прокси и разрешения тестового сертификата не входят в установленное расширение.

Проверены оба направления, страницы категорий Ozon с поисковым запросом, разбор JSON WB с ценами в копейках, ограничение до пяти карточек, цены и ссылки конкретных карточек, отсутствие автоматических вкладок и навигации, SPA-навигация, сворачивание, CAPTCHA и повтор, popup, выключение/включение, отмена HTTP при уходе со страницы. Отчёт: `test-results/widget-report.json`; снимки: `test-results/widget.png`, `test-results/popup.png`. Это тестовые названия и цены.

Прямой запрос JSON API WB из Node вне песочницы 19 ноября вернул HTTP 403. Успешное получение живой выдачи WB новым HTTP-режимом не подтверждено. Результат запроса из обычного Chrome может зависеть от cookies и ограничений площадки. При отказе код сообщает ошибку и не открывает страницу автоматически.

Для WB → Ozon в версии 0.2.2 добавлен запрос через существующую вкладку Ozon. `node scripts/ozon-native-probe.mjs` проверил именно production-модуль `ozon-session.ts` в обычном Chrome с отдельным профилем проекта. По запросу «худи мужское» получены HTTP 200 и пять настоящих товаров с названиями, ценами и каноническими ссылками. Парсится актуальный tileGridDesktop с полем textDS. Подробности: `test-results/ozon-native-session-live.json`. Это проверка модуля в контексте страницы; обмен сообщениями между расширением и вкладкой дополнительно проверяется браузерным тестом на контролируемых ответах. Полный пользовательский сценарий на живом WB в основном Chrome-профиле не запускался.

Отдельный тестовый Chromium с новым пустым профилем продолжает получать 403 даже на главной Ozon. Поэтому требуется открытая доступная вкладка Ozon в обычном Chrome; обход проверки безопасности не заявляется. Подробности отрицательной проверки — `test-results/ozon-session-live.json`.

18 ноября для прежней версии с фоновыми вкладками был запущен `npm.cmd run check:widget:live` с настоящими сайтами в новом видимом Chromium без пользовательской сессии. Ozon не завершил начальную загрузку за 30 секунд; поиск Ozon с WB завершился общим тайм-аутом 60 секунд. **Успешное получение живых цен в том запуске не подтверждено.** Подробности старого запуска: `test-results/widget-live.json` и `widget-live-*.png`.

Для пользовательской проверки установите `dist` в обычный Chrome, где обе площадки открываются. Установка и обновление описаны в [README](README.md). Временные профили нового теста удаляются после закрытия браузера; отчёты и снимки остаются.
