# Анализ и перестройка парсеров

## Исходный фрагмент

Присланный код использует общий абстрактный Parser и наследников для Ozon/Wildberries. Это подходящая основа разделения площадок. Но сам фрагмент собирает отзывы, тогда как актуальная схема db/marketplace_db_dump.sql и Wildberries в main.py собирают товары. Согласованный объём — товары.

Ошибки фрагмента:

- Chrome создаётся в теле класса при импорте и разделяется всеми экземплярами. Закрытие WB ломает следующие парсеры.
- У базового и дочерних get_data разные сигнатуры; timing не сохраняется в экземпляре.
- В WB массивы date/stars/likes/dislikes/reviews объединяются zip и обрезаются по самому короткому. При этом значения likes и dislikes попадают в неправильные колонки из-за порядка fieldnames.
- Индексы i.text[2] и i.text[5] извлекают один символ, а не полноценное количество голосов.
- Класс рейтинга выбирается по фиксированному индексу, дата — без проверки отсутствующего совпадения.
- В Ozon используется глобальная a.link вместо self.link; проверка «Комментарии» не соответствует regex «Комментарий».
- Заголовки CSV повторяются при каждом дописывании; исключения часто скрываются либо приводят к бесконечному ручному ожиданию.
- Встречаются фиксированные задержки и подмена Safari User-Agent в Chromium, не соответствующая реальному браузеру.

Поэтому код не копируется буквально. Общая архитектура сохранена, браузер создаётся на экземпляр при запуске; закрытие гарантируется finally. В проекте оставлен уже применяемый Playwright, чтобы не добавлять Selenium и скачивание ChromeDriver.

## Общий формат

Базой являются девять полей старого Wildberries: features, external_id, name, url, brand, price, old_price, rating, reviews_count. Они одинаковы у обеих площадок. Характеристики извлекаются общим features.py, десятичные значения передаются без float.

Вместо выбора трёх первых цен из всего body используются данные Product/Offer JSON-LD и локальные блоки цены. Отсутствие старой цены не мешает получить товар; цена из рекомендаций не подставляется. Неизвестные значения не заменяются нулём.

HTML-разбор можно запускать отдельно. Приведённые fixture-селекторы нужно проверять на фактически доступной версии страницы; поддержка JSON-LD не означает, что сайт всегда его публикует.

## Запись

Фактической ORM в новых файлах уже не было: models_simple.py содержит текст SQL. Сервер использует тот же SQL-слой через psycopg2. В db.py убрано дублирование запроса upsert.

Браузер не пишет в БД. Парсер → общий словарь → HTTP → проверка → транзакция PostgreSQL. База соответствует новому дампу: marketplaces/products/parse_runs/price_history/current_prices. old_price в дампе отсутствует и остаётся только в экспорте.

Пакет валидируется полностью до записи. Сначала фиксируется запуск; затем карточки, цены и завершение запуска записываются совместно. При сбое весь пакет откатывается, а failed фиксируется отдельно. Частичный сбор карточек не публикуется как успешный пакет.
